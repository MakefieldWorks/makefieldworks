Spacing, radii, shadows.
A 4px base, a narrow radius vocabulary, and shadows used sparingly. The goal is predictability across products — spacing choices shouldn't be re-invented on each screen.

Shadows · used sparingly
Prefer rules and flat surfaces over shadows. The only surfaces that consistently get shadows are the Opens-Calculator CTA, the top-layer dropdown/popover, and the terminal specimen on landing pages.
shadow-xs
Subtle lift on secondary buttons.
shadow-sm
Default floating card. Dropdowns.
shadow-md
Primary CTA. Popovers.
shadow-lg
Reserved: terminal specimens, modal dialogs, the floating sticky CTA on long landing pages. Large and soft, positioned downward. Never decorative.
Rules
DO
  • Stay on the 4px grid. No 7px / 13px one-offs.
  • Use radius-lg (12px) as the default card radius.
  • Prefer border-1 + var(--mw-rule) over shadow for card edges.
  • Use radius-pill for actions that feel like a commitment (Open Calculator, Plot Route).
DON'T
  • Don't stack shadows — one per element, max.
  • Don't use radius-2xl on standard cards — it's for hero surfaces only.
  • Don't invent a new shadow — if you need a different one, the design probably needs to be flatter.
  • Don't mix radii within a single component (e.g. rounded-lg card with rounded-md header).
